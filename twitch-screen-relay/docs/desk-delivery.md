# DESK delivery implementation boundary

The relay has complete structural codecs for DESK greetings, time, display controls, snapshots, extended STATS, events and device reports. They match the independent shared vectors. The classic session does not select or advertise DESK yet.

`DeskDelivery` is installed in the actual `DeviceHub`/`DeviceSession` path behind an explicit internal pairing gate. The default production listener still negotiates classic while shared reset and the complete failure matrix remain unfinished. Its greeting is a coherent immutable six-frame batch. Subsequent weather, CPU, display and STATS values occupy four latest-value slots. Ordered card references and explicit barriers occupy a bounded FIFO; retention overflow closes the connection before a successor can cross lost progress. Four clock-response slots are separate from card credit. WELCOME and TIME_RESPONSE take the supplied monotonic time at writer reservation.

A single writer reserves one immutable frame, performs I/O outside the owner monitor, then confirms complete flush. Uncertain failure closes rather than refunding credit. Reservation consumes send credit immediately but does not establish delivered progress or enqueue evidence. Only complete successful event writes add enqueue candidates; completely delivered barriers advance terminal progress without adding enqueue candidates or event credit. Reports must match current connection and boot identities, exact delivered control fences and source revisions, delivered progress, and cumulative pending-slot capacity. Duplicate reports do not reopen slots. Original retained card identities are deliberately not reinterpreted as current-session publication identities.

A report that races an outstanding write can occupy one replaceable deferred slot. `accept` returns `Right(false)` while deferring: the report is not authoritative and cannot grant credit yet. Successful completion revalidates the latest deferred report against the completed frame. Failed writes, invalid reconciliation, or expired application deadlines close the connection without applying the deferred report. Exact delivered histories are capped at 128 entries each; accepted observations prune older history, and exhaustion closes for resynchronization rather than accepting invented intermediate revisions.

Zero event credit does not block controls, weather, CPU or clock replies. After the immutable greeting, dirty display control always precedes other pending work, including new-generation STATS. The remaining clock, non-control state and ordered-event lanes rotate fairly; non-control state types also rotate within their lane. Ineligible Twitch cards and expired heads become ordered progress barriers without consuming credit. Twitch replay is suppressed. External events are not classified by their title or presentation kind. Card deadlines remain their original absolute deadlines.

The first-report timeout starts after SYNC_END flush; report and application timeouts reject late observations before mutation. Observation freshness uses calibrated observation time, not receipt time. Disconnect makes the last report historical, and no report proves physical pixels. Successful completion records the deferred report's original arrival time, not completion time. Duplicate, rejected and uncommitted reports cannot renew report liveness. The classic HELLO cursor never establishes capable enqueue authority: a valid same-epoch initial report may bootstrap its enqueue baseline only within the accepted processed resume boundary. Later enqueue claims require completely delivered event membership. Accepted control timestamps remain bounded; partial acknowledgments retire only applied revisions and advance the timeout to the earliest remaining acceptance. Heartbeat replies and requests participate in fair scheduling after the immutable batch and pending-control priority.

## Production publication precursor

`DeviceHub` now retains typed producer provenance with each notification in its existing bounded durable/chat rings. HTTP cards are external even when their kind or title looks like Twitch. Twitch producers explicitly label provider failures; relay-internal failures default to relay origin. Replayed legacy records without metadata remain unknown. Classic EVENT bytes, holds and ACK behavior are unchanged. HTTP responses now expose original provenance, source/episode fences and original-vs-remaining expiry using the canonical contract.

Each hub owns a nonzero random 64-bit relay epoch and a monotonic clock domain. Publications retain receipt time and their original absolute useful-lifetime deadline. Internal useful lifetime is validated independently of hold and defaults to 60000 ms. History reads never renew it. Classic receivers still cannot enforce waiting expiry. This metadata is mounted in notification HTTP responses and calibrated deadline admission; original nominal expiry remains distinct from the shorter accepted absolute deadline. GET /clock samples this same domain with Cache-Control: no-store. Shared wall/monotonic discontinuity reset and complete DESK writer enforcement remain pending.

`publicationSnapshot` captures epoch, clock sample, latest sequence, stable STATS revision/availability, bounded retained publications, confirmed desired control and original CPU/weather deadlines in one actor transaction. Attachment derives the immutable six-record greeting and replay prefix from that capture. Concurrent transition/publication tests verify the sequence/STATS/history relationship. Desired control includes cumulative display revision, source generation and Twitch episode, joined by the durable settings handoff. Actual gated session pairing is installed; this does not complete shared discontinuity, source replacement or default-production capability acceptance.

## Persisted-settings prerequisite

`RuntimeSettingsFile` and `RuntimeSettingsWorker` implement exercised durable storage. Production GET/PATCH /display now merges display-only intent through that worker and captures the projected hub response before another settings mutation. Monitoring mutation remains unmounted. Schema 1 stores both display fields and both monitoring fields only. The channel field is required and explicitly nullable in stored state; null is not a missing field. Unknown/duplicate keys, invalid sections, enum case and channel syntax are rejected. Reads are bounded to 16 KiB. A corrupt, exposed, wrong-owner, symlink or special-file input fails closed without rewriting it. New storage uses a private 0700 parent and 0600 file; existing unsafe parents are rejected rather than chmodded. This implementation requires POSIX filesystem permissions and atomic rename support.

Writes create their own unpredictable same-directory staging file, flush the file, atomically replace the target and sync its directory. Final symlinks and hardlinks are replaced, never written through. Cleanup removes only the writer's own staging path. Failure after rename is attempted returns an uncertain outcome with explicit actual readback; readback is not evidence that directory durability succeeded.

The separate Ox worker has a 16-command mailbox. It merges partial desired fields in serialized order and skips equivalent disk writes/revision increments. Persisted state wins over startup intent. Nonblocking snapshots expose last confirmed intent separately from storage uncertainty; uncertain failures latch subsequent mutations rather than projecting readback as a committed hub fence. Tests exercise concurrent disjoint updates and blocked fsync. Do not call disk storage inside DeviceHub or advertise C1/B1 acceptance from these tests.

### Installed startup and commit handoff

`Dependencies.create` now starts the settings owner before device listeners and source consumers. `runtime.settings-file` defaults to `data/runtime-state.json` and reads `RELAY_RUNTIME_STATE_FILE`; Compose places it in the retained `relay-data` volume beside, not inside, the OAuth token file. The parent must already be private if it exists. Invalid or unsafe stored state fails startup without replacement. First-run blank channel becomes explicit null.

Persisted monitoring mode and remembered channel select the actual Twitch source and alert rules after structural deployment parsing. Deployment secrets and provider configuration remain deployment-owned. Saved live intent without application prerequisites stays desired live while effective ingestion is disabled; generic TCP/HTTP listeners and notification publication remain available. `GET /api/v1/status` exposes read-only `startupMonitoring` desired/effective intent, settings source, transition and `configuration_missing`. This is startup diagnostics, not the canonical runtime monitoring API. First-run live intent still requires valid live prerequisites before listeners start. Selected live ingestion retains OAuth callback, scopes and webhook validation before provider construction. Runtime monitoring mutation, channel resolution, source replacement and OAuth teardown are not installed.

Initial settings and each successful durable commit enter the hub through a synchronous actor transaction. The atomic publication snapshot includes those confirmed settings and desired-control fences. Display revision advances for a display or monitoring change; source generation advances for monitoring mode/channel changes; Twitch episode advances for override or source changes. Preference-only edits do not advance episode, and identical handoffs do not advance any counter. A rapid disable/enable retains both episode increments even when a future writer coalesces control. Counters are checked before state mutation and never wrap. A monitoring change clears the current classic statistics snapshot but does not change epoch, sequence or generic retained records. Captured source views now reject obsolete callbacks/timers, but cancellation/join/recreation and live resolution are still required before runtime switching can be exposed safely. Admission accepts only an identical retry or the next consecutive revision; conflicting equal revisions, gaps and failed projections do not alter authority. Mutation acknowledgment waits for this handoff. A post-commit projection failure returns `runtime_unavailable` and latches subsequent writes; it does not imply rollback of the committed file. Storage uncertainty never reaches the projection callback. Recovery remains pending.

Tests run the actual production assembly twice with persisted simulated/CPU intent, bind and close real loopback TCP and HTTP listeners, and verify restart precedence and unchanged storage. Additional tests exercise the actual worker-to-hub handoff, rejected revisions, blocked projection and corrupt startup without listener binding. This is installed startup authority, not device display control or complete DESK synchronization. Production GET/PATCH /display now provides durable desired intent and serialized display revision. HTTP success is not applied-device proof; gated DESK/session pairing is installed but default production advertisement remains disabled. Weather readiness reflects the externally supplied latest slot; this is not evidence of physical application.
