Your sources. Your network. Your display.

The desk update keeps ingestion, selected display and data freshness separate. These are the target relationships, not a claim that every new path is implemented.

  1. Sources and clientsGeneric API producers, an opt-in Linux companion, external weather and optional Twitch integration.
  2. Private relayThe Scala relay accepts cards, holds latest telemetry and sends compact TSB/3 frames. The planned admin panel stays on this private origin.
  3. ESP32 and round LCDThe device presents cards and dashboards. Planned local orbits run without providers; retained eligible generic cards can finish offline.

Weather and CPU are unavailable when the relay link is down, even if a cached value has not expired. Active cards finish; stale or missing telemetry must not reappear underneath.

Keep management and the plain TCP device link on a trusted LAN or VPN. Never expose management ports publicly. The credential-free HTTP boundary in this checkout lets any reachable peer read and control the relay; network isolation is essential. Local private-HTTPS health, docs and notification read-back passed a certificate-verifying container smoke test. Real mobile trust and provider consent remain untested.

Build it, in a sensible order.

The root quickstart is credential-free in this checkout. Older guides are marked for migration; do not follow obsolete Basic/Bearer setup steps. The multi-purpose runtime remains incomplete.

  1. Start with software. Run the credential-free generic quickstart. No hardware, Twitch account or management token is needed. Remove obsolete nonempty auth settings before startup.
  2. Choose and measure your parts. Read the BOM, wiring and assembly guide. Target: ESP32 DevKit and a 240 × 240 round LCD. Board clones vary; physical enclosure fit remains a validation task.
  3. Print and configure. Inspect CAD sources and print exports, then configure and build firmware. Wi-Fi credentials belong on your device, never on this site.
  4. Add integrations deliberately. Read relay deployment guidance and optional Twitch setup. Provider consent and display selection are different actions.

Upgrade an existing deployment deliberately.

Old management credentials do not protect this checkout. Restrict reachable HTTP and device TCP to a trusted LAN or VPN before upgrading. Provider OAuth remains separate from management access.

Back up operator configuration, Twitch tokens and runtime intent privately. Do not delete grants or token volumes. HTTP hold duration is now 100–30000 ms; waiting expiry is separate. Legacy devices do not gain device waiting-expiry, control or report guarantees. Complete production DESK/1 and rollback acceptance remain pending.

Verify the installed path, not just a codec.

Use a separate test-owned relay and synthetic notification bus; never an existing service. The software runbooks exercise the installed companion, documented Compose deployment and native firmware application. Native LVGL observations are software evidence, not LCD pixels.

HTTP acceptance, socket-written reports and visible adapter revisions prove different layers. Numeric CPU/memory application needs matching measured values and presence fields, not just a revision. Default ESP32 DESK/1 advertisement and complete product acceptance remain pending. Physical checks need verified board ownership, private configuration, LCD observation and measured resource/soak evidence; live checks need verified provider and OBS prerequisites.

Finite software checks cover baseline/current peer compatibility, retained-eight reconnect and measured CPU/memory application. The baseline firmware row exercises transport and queue code, not an LCD. These checks do not accept the default ESP32, complete provider/suspend behavior or the private admin panel.

Correlate application views, numeric values and reports by relay epoch, connection and revision. Matching connection numbers alone cannot join observations across relay restarts. An unknown queue is not an empty queue. Keep unsupported, uncalibrated, stale and historical observations distinct from a fresh reported FIFO. Snapshot and pushed-feed evidence do not replace panel, deployment or LCD acceptance.

No request runs here. Read the mounted HTTP API guidance for your private deployment. ttlMs is screen hold duration; expiresInMs is the relay waiting lifetime. Both are accepted by the notification HTTP route in this checkout. Legacy devices cannot enforce waiting expiry after transmission. Complete DESK/1 device expiry and recovery acceptance remain pending. HTTP acceptance, enqueue ACK and firmware lifecycle reports are not proof of pixels.

Weather stays externally supplied. Companion CPU and memory are measured host values, not inferred ESP32 load. Forwarded notification content becomes readable by reachable relay peers and anyone near the physical display.

Explore the Linux companion deliberately.

The companion has installable source and isolated integration tests, not complete product acceptance. Supported desktop, installed service and physical display acceptance remain pending.

Notification forwarding starts disabled. After explicit enable, summary-only is the default; bodies need a separate opt-in. Application-name filters are not authenticated sender identities. Capture covers supported Freedesktop Notify submissions, not every portal or native notification path, guaranteed popups or remote cancellation.

CPU sampling and delivery stay independent when capture fails. Fresh CPU data does not prove notification capture is healthy. Missing memory is absent, not measured zero.
