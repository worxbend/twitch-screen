# Twitch Screen product site

A public static landing page, not the relay admin panel. The desk update is in development. Existing-source and planned claims are explicit; no full product, desktop, live-provider or physical acceptance is claimed. The target URL is https://worxbend.github.io/twitch-screen/; it is a deployment target, not proof of publication.

## Design and content

The circular, original orbital illustration carries the visual identity. Its manual synthetic card tour previews text and bodyless cards above either base appearance. Changing the appearance does not dismiss a card; “Finish illustration” reveals the current appearance and restores keyboard focus to the initiating control. Covered decorative arcs pause. The active card has an explicitly named accessible group; the covered SVG base leaves the accessibility tree until completion. Text cards expose title and body; bodyless cards omit the hidden body. Completion restores the accessible base and initiating keyboard focus. Chromium accessibility snapshots verify those transitions, not an actual screen-reader audit. The motion description updates at both card entry and completion, distinguishing card coverage from explicit user pause, reduced motion, unavailable observation and offscreen suspension. The pause control retains the user's independent preference; resuming it during a card does not restart covered arcs. IntersectionObserver and page-visibility events also suspend decoration when the illustration is offscreen or the document is hidden, preserving CSS animation phase and explicit pause intent. Page hide disconnects the observer; page show reattaches it without resetting an active card or appearance. Browsers without IntersectionObserver keep decoration static and label the disabled motion control “Motion unavailable”; card controls and reader links still work. No timers, scroll polling, storage or relay requests are added. These local steps are not device timers, delivery, queue simulation, physical layout proof or new runtime acceptance. Controls stay disabled when JavaScript is unavailable. Quiet editorial sections explain uses, the target architecture, build steps, synthetic API payload and limits. System fonts only. Tokens: background #080C12, surface #14212D, text #EDF5F7, secondary #A6BDC7, link/focus #78DCE8, boundary #708795. Device arc palettes are decorative, not text colors.

`content/features.json` is a reviewed, build-time public content ledger. It never imports workflow logs, private snapshots or live relay configuration. State is `existing` or `planned`, with a specific scope; source existence is not production acceptance. Every feature identity has an explicit accepted state in the builder; changing a planned row to `existing` fails the build. Promotions require integrator review and a matching validation-contract change. Keep unsupported desktop, physical smoothness, resource, fit and provider claims pending until their actual gates pass. Weather is externally supplied; no built-in collector. Notification forwarding starts disabled, then summary-only unless bodies are separately opted in. CPU freshness does not imply capture health.

`assets/provenance.json` covers the newly authored vector illustrations; no existing photos, CAD media, logos or downloaded fonts are bundled. Original site software is MIT and original illustrations CC BY 4.0. Root original-contribution license texts/mapping are now present. Full third-party rights remain integrator-owned prerequisites; this page does not claim that audit is finished. Code examples embedded in documentation remain MIT.

Only original site vectors are covered by the illustration-reuse reader. It links their public source, the checked-in full CC BY 4.0 text and the local provenance record. Credit, source/license links, change identification, retained notices/warranty disclaimer and lack of trademark/endorsement permission follow the materialized license map and CC BY 4.0 sections 2–3. Firmware artwork, photographs, imported CAD and binary dependency obligations remain explicitly outside that scope. No rights blocker is cleared by adding these links. The no-JavaScript browser journey checks exact targets, keyboard focus, >=44 px targets and local provenance readback at both bases, without following external links. This is an attribution/reader gate, not independent creator ownership or release clearance.

## Build and preview

Use CPython 3.12 (CI pins 3.12.12). Static build/preview need only the standard library. From repository root:

    python3 site/tools/build.py --base-path /twitch-screen/ --canonical https://worxbend.github.io/twitch-screen/
    python3 -m unittest discover -s site/tests -v
    python3 site/tools/preview.py --base-path /twitch-screen/ --port 8000

Open http://127.0.0.1:8000/twitch-screen/. Preview binds only loopback and stops with Ctrl+C. `--port 0` picks an unused test-owned port. The CLI and server reject ports outside 0–65535 before input admission or socket allocation; invalid CLI ports produce a concise error without a traceback. It requires one exact advertised `127.0.0.1:PORT` Host header; aliases, missing/duplicate Host and other authorities receive 421. Only origin-form requests and exact public-member paths are admitted; encoded/dot/double-slash aliases, symlink ancestors and unexpected regular files receive 404. Query strings do not expand that allowlist. Use the printed URL, not a `localhost` alias. This is a local development boundary, not the relay's production security implementation. It builds into an owned temporary directory, mounts only the selected base and never serves repository files. Root hosting works with `--base-path /`. Omit `--canonical` for a portable preview; explicit HTTPS canonical configuration must match the base path.

To inspect the exact prepared/downloaded static artifact rather than rebuilding source:

    python3 site/tools/verify_artifact.py site/dist
    python3 site/tools/preview.py --artifact site/dist --port 8000

Artifact preview derives the base from the manifest. An explicitly supplied different `--base-path` fails. It verifies membership/content, copies only the bounded public allowlist into an owned temporary snapshot, then verifies that snapshot before opening a listener. Later changes to the input directory cannot change served bytes. The input is never modified or removed; Ctrl+C removes only the preview snapshot. Local artifact inspection does not prove hosted execution or authorize publication.

The verifier prints `manifestSha256`, calculated from the exact admitted manifest bytes. Both prepared workflows already run this command before upload, so an authorized reviewer can obtain that identity from the exact successful run's verification log. Record the repository, workflow/run ID, event, head SHA and artifact name alongside the digest. A pull-request run's merge SHA may differ from its branch head; do not substitute one for the other. Verify the intended run and artifact through GitHub before downloading. A local digest or archive filename alone is not publisher authenticity or evidence of hosted execution.

To require those independently reviewed bytes when inspecting an extracted artifact or downloaded ZIP, add `--expected-manifest-sha256 DIGEST` to `verify_artifact.py`, `preview.py` or `browser_check.py`. Replace DIGEST with the exact 64 lowercase hexadecimal characters from the trusted verification result; do not derive the expected value from the untrusted download itself. Preview/browser pinning requires `--artifact` or `--archive`, never a source rebuild. A wrong or malformed pin fails before a preview listener or browser launch. The copied snapshot is checked again, preventing a second self-consistent build from replacing the reviewed identity during admission. Ordinary verification still checks all content hashes, public membership, provenance and payload rules; matching identity alone never bypasses them. GitHub's upload-artifact archive digest is a different value from this manifest digest and must not be used as its substitute. This is byte correlation, not a signature, rights clearance, environment approval or publication authorization.

For the ZIP downloaded from the artifact-only workflow, inspect it directly without manual extraction:

    python3 site/tools/preview.py --archive /path/to/twitch-screen-site.zip --port 8000
    site/.browser-venv/bin/python site/tests/browser_check.py --archive /path/to/twitch-screen-site.zip

`--archive` and `--artifact` are mutually exclusive. ZIP admission reads a regular, no-follow input once with a 16 MiB compressed-file ceiling, then accepts only the eight exact public files and an optional empty `assets/` directory. It rejects duplicates, path aliases/traversal, symlinks/special members, encrypted entries, unsupported compression and expansions over 8 MiB. Only stored/deflated entries are supported. Before ZIP member parsing, the end record must identify a single-disk non-ZIP64 archive with no trailing bytes, at most nine members and a central directory no larger than 64 KiB. The pre-parser also walks the actual directory records, checks their signatures and variable-length extents, enforces the same nine-member ceiling independently of the declared count, and rejects inconsistent counts, nonzero member disks, ZIP64 fields and malformed extra fields. Bounded unknown extra fields and ordinary ZIP comments remain supported. Content, CRCs, manifest, provenance and payload policy must pass before serving. Both extraction and preview use owned temporary snapshots; failure or Ctrl+C removes them without modifying the archive. This is not a general archive extractor: tar files, nested wrapper directories and the internal Pages deployment archive are not supported. The browser run checks the admitted snapshot as `inputMode=verified-artifact`, correlating its manifest hash; it does not certify the archive's origin, publisher identity or hosted workflow execution.

`site/dist/` is ignored, deployable output. Build writes only allowlisted HTML, CSS, JS, original SVG and attribution, plus `.nojekyll` and a deterministic SHA-256/size manifest. It rejects symlink sources/outputs, unknown output files, broken local/GitHub file targets and linked Markdown heading anchors, duplicate IDs, unresolved template tokens, unsafe paths, remote subresources, inline handlers, imports and network/polling primitives in the demo. Repeat builds are byte-identical. Before the first write, rebuild destinations admit only allowlisted regular files and required parent directories. Extra empty directories, FIFOs, sockets and file/directory type conflicts fail closed; incomplete owned builds can be restored without deleting unrelated files. No Node build runtime. Generated output is not source.

Checks revalidate illustration provenance on artifact read-back as well as build, including exact asset membership, licensing and nonphysical evidence flags. Artifact admission permits only regular allowlisted files and their required parent directories; unexpected empty directories, FIFOs, sockets and other special members fail before file reads. Manifest validation requires exact fields and types, nonnegative integer sizes, lowercase SHA-256 hashes, and an HTTPS canonical URL matching both the selected base and rendered canonical link. Malformed metadata produces a concise CLI rejection rather than a traceback. Recomputed manifest hashes cannot bypass these content rules. These checks enforce the selected artifact policy; they do not independently establish creator ownership.

The artifact and allowlisted source set are capped at 8 MiB uncompressed before reading. Artifact verification and preview copying additionally open each path component with POSIX no-follow directory descriptors, then admit the opened regular file with `fstat`. Nonblocking opens reject a replaced FIFO without waiting for a writer; opened-inode size checks and bounded reads retain the aggregate byte ceiling if a file grows after enumeration. Manifest compression uses the same admitted bytes, not a second mutable path read. These local tools require POSIX descriptor flags (supported on the Linux CI/verification target); there is no permissive fallback. This closes tested symlink/special-member replacement paths, not a claim of atomic filesystem snapshots or protection from an arbitrary same-user process. Snapshot content is still revalidated before serving. JSON metadata is capped at 64 KiB and 64 nesting levels; duplicate keys, non-finite numbers (including exponent overflow), and malformed feature items fail closed. Nested malformed manifests receive concise CLI errors without tracebacks. The complete compressed artifact must stay within 1.5 MiB. These bounds apply to build and artifact verification, not to relay runtime payloads.

## Reviewed hosted artifact handoff (read-only)

A maintainer must first identify the intended successful `pages-build.yml` run through an authenticated GitHub connection. Review its repository, event, exact head SHA, run ID, attempt and artifact ID; never use “latest”, a filename, or metadata from the downloaded archive as approval. For pull requests, use the workflow run's actual head SHA, which may be a merge SHA, not a guessed branch SHA. No hosted Pages run is accepted by this checkout's local results.

Save these two read-only API responses outside `site/dist/`, replacing RUN_ID with the independently reviewed numeric ID:

    gh api repos/worxbend/twitch-screen/actions/runs/RUN_ID > run.json
    gh api 'repos/worxbend/twitch-screen/actions/runs/RUN_ID/artifacts?per_page=100' > artifacts.json

Run the offline guard with the independently reviewed values, not values inferred from the untrusted download:

    python3 site/tools/check_hosted_identity.py --run-json run.json --artifacts-json artifacts.json --run-id RUN_ID --artifact-id ARTIFACT_ID --head-sha HEAD_SHA --event EVENT

The guard checks the exact repository/workflow/run/head/event, successful completion, selected artifact ID and SHA-derived name, matching run/repository/head-repository IDs and branch, nonexpiry, bounded ZIP size, archive digest syntax and exact GitHub download endpoint. It requires a complete inventory of at most 100 artifacts; partial pagination fails closed. Fork PR head repositories are valid only when their exact IDs match the run. Reruns are intentionally refused: artifact metadata does not identify the producing attempt unambiguously. Obtain separate manual attempt/log/artifact review rather than reinterpreting an older artifact as the latest successful attempt. Metadata is bounded to 64 KiB per file, read without symlink following, and duplicate/nonfinite/malformed JSON rejects with a concise error.

`metadata-matched` means only consistency with the supplied expectations. Without an archive, `archiveBytesMatched` is false. The tool does not authenticate saved metadata, fetch anything, approve environments, dispatch workflows, download artifacts or authorize publication. Tests use explicitly synthetic metadata. A matching artifact archive digest is not the static manifest digest. Keep both identities distinct.

## CI and publication boundary

`pages-build.yml` builds/tests and uploads a static artifact on push, PR or manual build. Its path filters include linked relay, firmware, companion and CAD inputs as well as documentation, fixtures and licenses. A source-driven test checks both push and PR coverage against the actual feature references and HTML repository links. These checks catch deleted or changed claim sources without promoting their availability. It has only `contents: read`; no Pages/OIDC permission and no public deployment. Fork PRs do not use `pull_request_target`. Browser dependencies are test-only and action references are immutable commit SHAs.

`pages-deploy.yml` is manual only on `main`. It requires an explicit `publish` confirmation, rebuilds the exact dispatch SHA, reruns gates and deploys through the `github-pages` environment. It does not accept arbitrary artifact names, cross-repository artifacts or unvalidated ref input. Build permissions stay read-only; only the deploy job gets Pages/OIDC writes. Environment approval/protection must be configured by an authorized maintainer; the workflow does not configure it or enable Pages. A manual workflow file is not authorization to run it. No deployment has been performed by this implementation.

Before any authorized publication: finish F license/docs reconciliation, approve feature statements against independently verified tracks, review browser security baseline and environment protection, then validate the actual served URL/base/links separately. Local build/browser success cannot prove GitHub Actions execution, site publication or product completion.
