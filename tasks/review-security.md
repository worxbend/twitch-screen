Validation: eight focused suites pass 74 tests: ConfigSuite (19), ManagementAuthSuite (7), ManagementRoutesSuite (4), TwitchRecoverySuite (6), TwitchAuthSuite (12), EventSubWebhookSuite (13), ChannelStateTrackerSuite (11), WebhookDeduplicationSuite (2). The independent reviewer reran the same suite set successfully. Scalafmt and diff whitespace checks pass. Root performs the combined suite and Docker/SIGTERM smoke after integration; Main preserves its ApplicationLifetime shutdown wrapper.

No live Twitch credentials are available. Actual provider acceptance remains a deployment check; local tests use the pinned provider decoder, actual HTTP server, scripted Helix adapters and controlled state transitions. The management tests cover all assembled endpoints rather than substituting a single representative route.

Operator contract: `RELAY_HTTP_AUTH_BASIC_USERNAME` plus `RELAY_HTTP_AUTH_BASIC_PASSWORD_HASH`, or `RELAY_HTTP_AUTH_API_TOKEN`, or both. At least one complete valid method is mandatory. Password hashes use `pbkdf2-sha256$600000$<base64 salt>$<base64 digest>` generated by `tools/hash_management_password.py`; preserve literal dollar signs when exporting. Bearer tokens contain at least 32 bytes from the ASCII Bearer alphabet (for example `openssl rand -hex 32`). Restart to rotate static credentials. Password checks beyond two concurrent derivations return JSON 503 and may be retried.

Recovery contract: listeners bind before ingestion/subscription work; recoverable initialization retries at 1, 2, 4, 8, 16, 32, then 60 seconds. Webhook reconciliation and chat/subscription health checks run every 30 seconds. WebSocket failures or grant changes rebuild the scoped client within a maintenance cycle. Token maintenance withholds expired/rejected tokens and retries refresh; sign-out serializes local removal from memory, shared credential handle and disk before attempting provider revocation. Health reports Connecting, Connected, Degraded or Disconnected from ongoing component observations.
