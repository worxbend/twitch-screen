Real decoder fault regression (plain custom int main test, no Unity dependency).
Run from twitch-screen-firmware; parent owns PlatformIO test-filter integration.

Direct native sanitizer command:
  g++ -std=c++11 -Wall -Wextra -Werror -g -O1 -fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer -I src src/generic_input.cpp src/generic_decode.cpp test/test_generic_decode_fault/test_generic_decode_fault.cpp -o ../.agent-workflow/standalone-generic/decoder-fix/fault-test
  ../.agent-workflow/standalone-generic/decoder-fix/fault-test

The real 2732-byte JPEG and upstream reference are READ from the existing
sibling test_generic_view/photo96.jpg and photo96.rgb565, never rewritten.
RED proved body lengths454/455/456 (prefix cuts452/453/454 + FF D9) passed marker
framing, decoded successfully and overwrote the output before the entropy fix.
The test also rejects every prefix cut inside each of that real image's ten
entropy regions, mid-scan deletion with subsequent scans preserved, premature
restart/EOI, missing and all out-of-sequence restart indices, and RST without DRI.
Each rejected call must return false, leave the sentinel RGB565 output unchanged,
leave zero live decoder allocations and remain within the aggregate64KiB cap.
The publication counter models only the decoder caller's success condition;
service/worker publication integration remains the parent's separate gate.
Markerless truncation, exact dimensions, encoded8KiB and OOM remain controls.

Generated controls have explicit non-provider provenance:
  /usr/bin/python3 test/test_generic_decode_fault/generate_fixtures.py
Pillow's installed system encoder reports JPEG library8.0. Pixel formulas and
quality65 are in that script; images are exactly96x96, L or RGB, baseline or
progressive, subsampling0/1/2 (4:4:4/4:2:2/4:2:0) with restart intervals0 or3.
Sixteen JPEGs are real libjpeg-encoded streams, not handwritten pseudo-JPEGs.
The .rgb565 files were generated by the parent's compare_reference.cpp compiled
against independently downloaded pristine stb_image2.30, commit
2c980bb59875b0d32144a71867fbdebb2f77cd20, SHA256
594c2fe35d49488b4382dbfaec8f98366defca819d916ac95becf3e75f4200b3.
RGB565 references store native little-endian uint16_t on this Linux/ESP32 target.
Do not replace them with the production decoder's output.

Production-cap valid controls: grayscale baseline/progressive, color baseline
4:2:2/4:2:0 and progressive4:2:0, each with/without restarts. Color4:4:4 and
progressive4:2:2 intentionally exhaust the unchanged aggregate budget; their
failure must not write output. Their pristine references also permit independent
uncapped vendor comparisons to prove strict entropy checks preserve valid JPEGs
without misrepresenting those layouts as supported by the capped application.

No board/serial/network access is needed by these tests. Actual additional
provider files are compared by decoder-fix/verify_reference.py using the parent's
previously downloaded untouched files, not substituted generated controls.
